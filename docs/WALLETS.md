# Read-only wallets

Run `hcs-trader eth-balance ADDRESS` to read a native ETH balance from an operator-managed node on `127.0.0.1:8545`. Use `--port` for another local port. Provide a lowercase 20-byte hex address with the `0x` prefix. The address is public. The command does not need an account unlocked at the node.

The adapter checks that the node reports chain ID 1, obtains a finalized block and requests the balance at that block's canonical hash. The node must support the EIP-1898 block identifier. The result includes the canonical native asset ID, block number and hash, local observation timestamp, and exact wei as a decimal string. This identity check relies on the operator's node and its sync state. [Ethereum JSON-RPC](https://ethereum.org/developers/docs/apis/json-rpc/) · [EIP-1898](https://eips.ethereum.org/EIPS/eip-1898)

Use `eth-balance ADDRESS --network sepolia --port PORT` and `tx-status eth-sepolia HASH --port PORT` with a loopback Sepolia node. The same finalized and canonical-block checks apply after verifying chain ID 11155111. Sepolia uses asset ID `eip155:11155111/native:ETH`. Saving a Sepolia balance writes `wallet-sepolia.sqlite` alongside the default database. The default wallet API and dashboard read only the default database.

On 2026-11-15, the CLI read a balance at finalized Sepolia block 12,142,379 and verified the canonical receipt for transaction `0xdd52cbb1d292e0f437d436db8eb7d9f0d4053d3e37309daffa10b9d722b77e1b`. The Mainnet profile rejected the same endpoint before requesting a balance. The check used a temporary read-only loopback relay to PublicNode, with an isolated data directory. [PublicNode Ethereum endpoints](https://ethereum.publicnode.com/)

Run `hcs-trader sol-balance ADDRESS` for native SOL using a node on `127.0.0.1:8899`. The command validates a 32-byte base58 public address, compares the node's genesis hash with mainnet-beta and requests finalized commitment. It reports exact lamports as a decimal string and the returned slot. [Solana balance RPC](https://solana.com/docs/rpc/http/getbalance) · [Genesis hash RPC](https://solana.com/docs/rpc/http/getgenesishash)

Use `sol-balance ADDRESS --network devnet --port PORT` or `tx-status sol-devnet SIGNATURE --port PORT` with a loopback Devnet node. This profile pins the full Devnet genesis hash `EtWTRABZaYq6iMfeYKouRu166VU2xqa1wcaWoxPkrZBG`. It uses a distinct SOL asset ID and stores optional snapshots in `wallet-devnet.sqlite` alongside the default database.

On 2026-11-15, the CLI read a finalized Devnet balance with context slot 522,661,439 and verified a successful finalized transaction at slot 522,388,640. Mainnet rejected the same endpoint on the genesis check. The read-only test used a temporary loopback relay to the official Devnet RPC and an isolated data directory. [Solana cluster endpoints](https://solana.com/docs/references/clusters) · [Observed transaction](https://explorer.solana.com/tx/43GbogaVyiA8UxDQRzWAAHGJMrmVjDqB6dE1rQXBbXebtuaTtoL25fYZ1qVrGw4tk2n8SYaFFdL9Y9Rw3S2dZmHY?cluster=devnet)

Run `hcs-trader btc-balance ADDRESS --cookie-file PATH` for the confirmed UTXOs matching a public Bitcoin address. Use a synced Bitcoin Core mainnet node on `127.0.0.1:8332` with JSON-RPC 2.0 support. The command reads the node's local authentication cookie and validates the address with Core before requesting a single `addr(...)` descriptor scan. It reports the scan block and exact satoshis. An explicit scan can take time and uses the node's UTXO scanning facility. The result covers matching confirmed unspent outputs at the scan block, including any immature outputs returned by the node. [Bitcoin Core scan documentation](https://bitcoincore.org/en/doc/30.0.0/rpc/blockchain/scantxoutset/)

Select `--network regtest` or `--network signet` for the corresponding Bitcoin Core profile. Default RPC ports are 18443 and 38332 respectively. Each profile validates the chain name and genesis, and the Signet profile additionally pins the public Signet challenge. Pass the cookie file for the selected node. `--save` uses `wallet-regtest.sqlite` or `wallet-signet.sqlite`. [Bitcoin Core 30.4 chain parameters](https://github.com/bitcoin/bitcoin/blob/v30.4/src/kernel/chainparams.cpp)

On 2026-11-15, an isolated Bitcoin Core 30.4 Windows x64 node with networking disabled mined 101 regtest blocks to a local test address. The CLI observed 505,000,000,000 satoshis at height 101 and saved the snapshot to the separate regtest database. Mainnet and Signet each rejected the regtest node. A second offline node confirmed the default Signet genesis and challenge at height zero. A scan against a synchronized public Signet node remains pending. [Bitcoin Core 30.4 distribution](https://bitcoincore.org/bin/bitcoin-core-30.4/)

`ltc-balance ADDRESS --cookie-file PATH` and `dgb-balance ADDRESS --cookie-file PATH` use the same confirmed UTXO scope with local Litecoin Core and DigiByte Core nodes. Default mainnet RPC ports are 9332 and 14022 respectively. Both use the legacy RPC reply shape. All three UTXO commands check the exact chain genesis hash before address validation and scanning. The Litecoin scan covers transparent address scripts. [Litecoin Core v0.21.5.8](https://github.com/litecoin-project/litecoin/releases/tag/v0.21.5.8) · [DigiByte Core v9.26.7](https://github.com/DigiByte-Core/digibyte/releases/tag/v9.26.7)

Select `--network regtest` for Litecoin Core on port 19443 or DigiByte Core on port 18443. With `--save`, each writes to its own database, `wallet-litecoin-regtest.sqlite` or `wallet-digibyte-regtest.sqlite`. On 2026-11-15, the pinned Windows x64 daemons ran with network connections disabled and produced 10 regtest blocks each. The CLI matched their scan tip hashes and read 50,000,000,000 Litecoin base units and 72,000,000,000,000 DigiByte base units. Both mainnet profiles rejected their regtest nodes. DigiByte block generation used `-easypow`. Public testnet and mainnet scans remain unverified in these configurations.

Use `hcs-trader tx-status eth HASH` or `hcs-trader tx-status sol SIGNATURE` for a known transaction identifier. Ethereum compares the receipt against the canonical block at its height and compares that height with the finalized head. Solana reports the confirmation status returned by the node's signature history. Both report execution success separately from finality. `unknown` means the node returned no receipt or signature status. The transaction may be pending, unknown to that node or outside its available history.

Address-wide transaction history, token balances, address derivation, signing and broadcast are separate milestones.

Add `--save` to any balance command to keep the most recently observed snapshot for that chain and public address in local SQLite. `GET /api/v1/wallets` serves those snapshots offline with their original observation time and block or slot. These are previously observed balances. A fresh read requires rerunning the relevant command against the local node. A regular balance command prints its result without saving it.
